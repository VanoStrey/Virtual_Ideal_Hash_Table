# Virtual Ideal Hash Table (VIHT)

**Виртуальная идеальная хеш-таблица** — новый метод предвычислений для мгновенного поиска прообразов криптографических хеш-функций.  
Архитектура обеспечивает **O(1)-доступ** (одно чтение с диска) без какой-либо сортировки данных.  
На MacBook Air M2 достигается пропускная способность **>2 600 успешных запросов в секунду** при среднем времени поиска **0,38 мс**.

---

## Ключевые особенности

- **Мгновенный поиск** – одно чтение 32 байт с диска.
- **Пропускная способность** – более 2 600 поисков/с в однопоточном режиме.
- **Отсутствие сортировки** – построение эквивалентно полному брутфорсу, но выполняется один раз.
- **Гарантированное 100% покрытие** заданного пространства.
- **Переменная длина** – строки от 1 до 5 символов упаковываются в 4 байта.
- **Устойчивость к перезапускам** – чекпоинты позволяют продолжить построение.
- **Многопоточность** – lock‑free архитектура, используются все ядра CPU.
- **Лёгкая адаптация** к другим хеш‑функциям и алфавитам.

---

## Как это работает

### Идея виртуальной идеальной таблицы
Если бы можно было создать файл с 2²⁵⁶ ячейками, поиск прообраза свёлся бы к чтению ячейки по индексу хеша.  
Это и есть **идеальная** хеш‑таблица, физически нереализуемая.

**Виртуализация** использует только младшие 28 бит хеша (268 млн слотов).  
Каждый слот содержит до 8 ячеек по 4 байта.  
Благодаря равномерности SHA‑256 коллизии (более 8 записей в слоте) практически исключены.

### Упаковка прообразов
Алфавит `[A-Za-z0-9]` (62 символа) + пробел как технический ноль.  
Строка дополняется пробелами до 5 символов и интерпретируется как число в системе счисления 63 (помещается в 4 байта).  
Это даёт однозначное кодирование любых строк длиной 1–5.

### Построение таблицы (однопроходное, многопоточное)
1. **Генерация прообразов:** все 931 млн индексов раздаются потокам через `AtomicLong`.
2. **Хеширование:** для каждого прообраза вычисляется SHA‑256, определяется слот.
3. **Атомарное выделение ячейки:** `AtomicIntegerArray.getAndIncrement(slot)` — без блокировок.
4. **Запись:** `FileChannel.write(ByteBuffer, position)` — потокобезопасная позиционная запись.
5. **Чекпоинты:** счётчики заполнения сохраняются в off‑heap файл `slot_counts.bin`. При перезапуске строитель загружает их и продолжает.

### Поиск
- SHA‑256 → младшие 28 бит → индекс слота.
- Чтение слота (32 байта) через сегментированный `MappedByteBuffer`.
- Проверка до 8 ячеек: распаковка, вычисление SHA‑256, сравнение.
- Вторичное хранилище (`secondary_sorted.bin`) практически не задействовано.

## Быстрый старт

### Требования
- JDK 21+
- Maven 3.8+
- Свободно ~10 ГБ на диске

### Сборка
```bash
git clone https://github.com/foolvan/Virtual_Ideal_Hash_Table.git
cd Virtual_Ideal_Hash_Table
./mvnw clean compile
```

### Построение таблицы
```bash
java -cp target/classes org.examle.vht.Main
```
Выбрать **1** (Build table). Построение занимает 15–30 мин на M2.  
Создаются файлы `primary_table.bin`, `slot_counts.bin`, `secondary_sorted.bin`.

### Поиск
```bash
java -cp target/classes org.examle.vht.Main
```
Выбрать **2** (Search hash interactive), вводить SHA‑256 (64 символа).  
Выход — `exit`.

### Бенчмарк
```bash
java -cp target/classes org.examle.vht.OptimalVHTBenchmark
```
10 000 случайных поисков с выводом средней задержки и пропускной способности.

## Конфигурация
`Config.java` содержит основные параметры:
- `ALPHABET` – строка символов (по умолчанию `[A‑Z][a‑z][0‑9]`)
- `MAX_STRING_LENGTH` – максимальная длина (5)
- `SLOT_INDEX_BITS` – бит под индекс слота (28)
- `CELLS_PER_SLOT` – ячеек в слоте (8)

Количество прообразов вычисляется как сумма `BASE¹ + ... + BASEᴸ`.

## Сравнение с аналогами
| Метод | Время поиска | Предвычисления | Покрытие | Работа с солью |
|-------|--------------|----------------|----------|----------------|
| **VIHT** | 0,38 мс | десятки минут | 100% | Требует новой таблицы, но построение очень дёшево |
| Радужные таблицы | секунды‑минуты | часы‑дни | 80‑90% | Неприменимы |
| Полный брутфорс (GPU) | часы‑годы | нет | 100% | Не зависит |
| Полная таблица | < 1 мс | астрономическое | 100% | Теоретически возможна, но нереализуема |

VIHT сочетает мгновенный поиск с низкой стоимостью предвычислений, что делает её пригодной для построения под конкретную соль.

## Ограничения и перспективы
- Работает с бессолевыми хешами либо с заранее известной солью.
- Размер таблицы пропорционален пространству перебора, но современные SSD вмещают десятки гигабайт.
- Для максимальной производительности запись можно перевести на mmap.
- Алфавит и длина легко настраиваются.
- Представляет интерес для формального анализа time‑memory trade‑off в криптоанализе.
